## 1. 视觉方向决策（拍板）

**选定：以方案 A（专业科技风）为全局基调，话术锦囊模块融合方案 B（温馨陪伴风）元素。**

### 理由

1. **相机类 App 的 UI 共识不可违背**：取景器优先、深色默认、控件克制（Halide / 原生相机均如此）。方案 B 的暖色全局皮肤会削弱专业感，方案 C 的杂志风偏离 P0 情侣场景。
2. **P0 场景是双边体验**：拍摄者（多为男生）对「专业工具感」有信任需求；被拍摄者对「情绪价值」有放松需求。A 服务前者，B 服务后者，按模块划分而非二选一。
3. **融合点收敛在一个模块**：话术锦囊以聊天泡泡样式呈现 + 珊瑚橙暖色点缀，其余全部遵循 A 的冷色专业体系。暖色不进入取景器主控件，避免视觉竞争。

### 否决记录

- 纯 A：话术锦囊情绪感不足，丢掉产品差异化的一半。
- 全局 B：专业感不足，拍摄者不信任，男生嫌幼稚。
- C：服务 P2 社交达人，偏离已确认的 P0 情侣场景。

## 3. 交付物一：高保真视觉原型 `prototype-hifi/`

### 定位

替代 Figma 高保真稿的第一步：在浏览器中以接近最终视觉的水准呈现核心流程，供用户（及后续可用性测试参与者）体验与评审。流程逻辑沿用 `prototype/`（低保真）已验证的页面流，视觉全部重做。

### 文件结构

```
prototype-hifi/
├── index.html        # 单页承载全部屏幕，JS 切换
├── style.css         # 设计系统 + 全部样式
└── app.js            # 屏幕切换与演示交互
```

### 页面清单（5 屏）

1. **启动页**：品牌名 + 一句话定位，青色呼吸光效，点击进入。
2. **模式选择**：两大卡片（「帮 TA 拍」「我们合照」），毛玻璃卡片 + 青色选中态。
3. **场景选择**：约会场景列表（咖啡厅 / 街拍 / 夜景 / 室内），配图式卡片。
4. **取景器（核心屏）**：
   - 全屏模拟取景画面（渐变占位图，深色氛围）
   - AR 姿势虚线轮廓叠加（青色，局部红色高亮未匹配部位）
   - 顶部：焦段建议胶囊（毛玻璃）
   - 底部：快门区（白色圆环快门 + 缩略图 + 翻转）
   - AI 摄影师指导面板：底部毛玻璃卡片，一条实时建议
   - 话术锦囊：右下角珊瑚橙泡泡按钮，点开为聊天泡泡式锦囊列表（B 元素唯一入口）
5. **AI 点评**：拍摄完成后的点评页，评分 + 构图/姿势/情绪三条反馈 + 重拍/保存按钮。

### 呈现方式

桌面浏览器打开时以 390×844（iPhone 尺寸）手机框居中展示，框外深色衬底；手机内按全屏 App 渲染。

## 4. 交付物二：姿势识别技术验证 Demo `pose-demo/`

### 目的

验证项目最危险的假设：**实时姿势识别在普通设备上是否足够快、足够稳**，能否支撑 AR 姿势引导的产品体验。这是 CV 核心的第一次技术接触。

### 技术方案

- 纯浏览器实现，无构建步骤：单 `index.html` + `app.js` + `style.css`
- 模型：MediaPipe Tasks Vision **PoseLandmarker**（CDN 加载 `@mediapipe/tasks-vision`，模型文件用 Google 托管的 `pose_landmarker_full.task`）
- 摄像头：`getUserMedia`，`detectForVideo` 逐帧检测，33 个关键点
- 渲染：Canvas 叠加骨架连线与关键点，随视频帧率刷新

### 验证指标（页面上实时显示）

1. **FPS**（检测循环帧率）——目标 ≥24
2. **单帧检测耗时 ms**——目标 ≤40ms
3. **关键点数量与可见人数**
4. 骨架稳定性（目测，连续帧不剧烈抖动）

### 边界（YAGNI）

- 不做姿势匹配/打分逻辑，不做引导线生成——只验证「识别能力」本身
- 不做录制、不做多模型切换，模型固定 full 版
- 需通过 `http(s)://` 或 `localhost` 打开（摄像头权限要求），README 注明启动方式
