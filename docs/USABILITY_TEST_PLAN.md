# Pose相机 / PoseCam 可用性测试计划（高保真原型轮）

> 版本：v0.1  
> 日期：2026-07-17  
> 状态：待执行（原型已通过发起者评审，进入可用性测试阶段）  
> 基于：`docs/PRD.md`、`docs/research_report.md`、`docs/MVP_PLAN.md`  
> 前置条件：本计划全部任务基于高保真可点击原型 `prototype-hifi/`（`index.html` + `style.css` + `app.js`，纯静态、file:// 可直开）。原型共 5 屏：启动页 → 模式选择（帮 TA 拍 / 我们合照）→ 场景选择（咖啡厅 / 街拍 / 夜景 / 室内）→ 取景器（AR 轮廓 + 焦段胶囊 + AI 面板 + 话术锦囊）→ AI 点评。**原型是浏览器点击式演示，不是真实相机**：取景画面为 CSS 渐变模拟、快门只触发闪白并跳转点评页、「保存照片」仅弹出 Toast。测试设计已针对此预期差做专门处理（见第 4 节）。

---

## 1. 测试目标

本轮测试用高保真原型验证：核心体验 triad（AR 姿势引导 + 构图/焦段建议 + 话术锦囊）在真实目标用户面前是否**看得懂、用得上、愿意用**。具体四个目标：

| # | 目标 | 关键问题 | 对应任务 |
|---|---|---|---|
| G1 | 核心流程可理解性 | 从启动页到取景器能否无师自通？「帮 TA 拍 / 我们合照」两个模式、四个场景是否自解释？默认选中态会不会被当成"已帮我决定"？ | T1、T6 |
| G2 | 取景器信息层级 | AR 轮廓、焦段胶囊、AI 面板、锦囊按钮、快门区同屏，是否打架或过载？用户注意力先落在哪？红色「右臂再抬高一点」提示给谁看、看得懂吗？ | T2、T4 |
| G3 | 话术锦囊的发现率与使用意愿 | 不提示的情况下，拍摄者多久能发现右下角的锦囊入口？发现后会不会真的照着说？哪类话术"说不出口"？ | T3、T2（顺带观察） |
| G4 | 双人协作摩擦点 | 一人持机、一人被拍时，引导信息在两人之间如何流转？被拍者看不到/看不懂引导怎么办？有没有抢手机、尬住、角色冲突？ | T3、T6 |

附带的顺带观察（不单独设任务）：AI 点评页的价值感知与「保存 / 再拍一张」决策（T5）；闺蜜组对模式命名的反应（PRD 有「闺蜜模式」概念，原型只有「帮 TA 拍 / 我们合照」，留意 P1 组是否期待闺蜜专属入口）。

**本轮不测**：性能、AR 精度、真实成像质量（原型阶段无从测起）；付费转化（仅在简访中口头验证付费意愿）。

## 2. 测试对象与筛选

### 2.1 样本设计

| 组别 | 数量 | 构成 | 说明 |
|---|---|---|---|
| P0 情侣/夫妻 | 3–5 对 | 每对 2 人同场测试 | 核心验证对象，优先保证 |
| P1 闺蜜 | 2 组 | 每组 2 人同场测试 | 验证模式的延展性 |

- 共 **5–7 场**，每场 2 名参与者 + 1 名主持人（即发起人本人），约 50–60 分钟。
- 规模按「一个人业余时间可跑完」设计：两个周末、每天 2–3 场即可完成；整理记录每场约 30 分钟。
- 测试伦理：开场口头告知「仅用于产品设计研究、可随时退出、录音录屏仅内部使用」并征得同意；未成年人不纳入。

### 2.2 筛选问卷（招募时线上填写，用腾讯问卷/问卷星搭建）

1. **你的年龄段**：18–25 / 26–30 / 31–35 / 35+
2. **你和搭档的关系**：情侣 / 夫妻 / 闺蜜 / 其他____；在一起/认识多久了？____
3. **你们互相拍照的频率**：每周 ≥3 次 / 每周 1–2 次 / 每月几次 / 很少
4. **平时拍照的分工**：基本固定一方拍 / 互拍差不多 / 自拍为主，很少互拍
5. **近 3 个月有没有因为拍照闹过不愉快**：经常 / 偶尔 / 几乎没有；如选前两项，请简单讲一次经历____
6. **你和搭档的手机型号**：____（如 iPhone 15 / 小米 14 等，两人都要填）
7. **用过以下哪些产品**（多选）：可颂 / 美姿构图相机等姿势类 App / 华为 AI 构图、荣耀灵感帮拍 / 都没用过
8. **你的职业**：____

**筛选通过标准**：
- P0 组：恋爱或婚姻关系；Q3 至少「每月几次」；Q4 存在相对固定的拍摄分工；Q5 选「经常/偶尔」者优先（痛点最强的用户）。
- P1 组：18–30 岁女性双人组；每月至少 1 次探店/Citywalk/旅行拍照。
- **排除**：职业摄影师、摄影类博主/KOL、UX/用研从业者；近 3 个月参加过其他 App 测试者；发起人的直系亲属与密友（避免恭维偏差，优先二度人脉）。
- Q6 仅做记录，不作为筛选门槛（测试统一用主持人自备的 iPhone 演示）。

## 3. 任务脚本

### 3.1 使用说明

- 共 6 个任务：T1–T5 每场必做，按顺序进行；T6 为机动任务，时间充裕时做。
- 「任务描述」栏是**直接照读给用户的话术**；方括号内需按现场情况替换。
- 通则：参与者卡住时先等 60 秒；确需提示时用两级提示——先问「你觉得可以怎么办？」，再给方向不给答案（如「看看屏幕右下角」而不是「点那个橙色按钮」），并在记录表标注「提示后完成」。

### 3.2 T1 首次进入：这是个什么 App？（对应 G1）

- **任务描述**：「你现在拿到了朋友推荐的一个新 App，叫 PoseCam。请从第一屏开始，像平时用新 App 一样自己探索，想到什么就说什么。这次没有任务，走到你觉得『可以开始拍照了』的地方就停下来。」
- **成功标准**：无提示从启动页走到取景器（启动页点击 → 模式选择 → 下一步 → 场景选择 → 进入取景器）；能口头说出模式、场景两个页面分别是在选什么。
- **观察点**：
  - 启动页 slogan「你的随身 AI 摄影师 / 让每一次快门，都恰好心动」是否让人明白产品用途，还是会误以为是美颜/修图 App；
  - 「帮 TA 拍 / 我们合照」是否自解释，有没有反问「这是什么意思」；默认选中「帮 TA 拍」是否被注意到，还是直接点了「下一步」；
  - 场景卡的选择依据（看名字？看描述文案？还是默认第一个）；
  - P1 闺蜜组是否寻找「闺蜜模式」之类的入口。
- **完成后追问**：
  1. 「用一句话告诉我，这个 App 是干什么的？」
  2. 「这两个模式，你们分别在什么时候会选？」
  3. 「刚才的场景你为什么选了 [XX]？」

### 3.3 T2 取景器里有什么？（对应 G2）

- **任务描述**：「假设你们现在真的就在这家咖啡厅，准备开拍。先别急着按快门——看看这个画面，告诉我：屏幕上这些东西你们觉得分别是干嘛的？你们第一步会做什么？」
- **成功标准**：两人合计能正确说出 ≥3 个元素的用途（AR 姿势轮廓、焦段胶囊、AI 摄影师面板、话术锦囊按钮、快门区）；没有因界面产生明显的「我不知道该干嘛」。
- **观察点**：
  - 注意力顺序：第一眼落在哪（轮廓？AI 面板大字姿势名？快门？）；
  - 是否主动说出「信息太多/太乱/字太小」，或反之觉得「挺清楚」；
  - 红色未匹配提示「右臂再抬高一点」：是否被看到？两人是否明白这是给**被拍者**看的姿势纠错？
  - 顶部胶囊「建议焦段 2x · 半身特写」：是否被注意？是否理解 2x 含义？会不会伸手去点它（原型中它不可点击）？
  - AI 面板右上角「换一条」刷新图标是否被发现（不提示）；
  - 右下角橙色「话术锦囊」按钮在此刻是否已被注意到（记录，为 T3 的发现率做对照）。
- **完成后追问**：
  1. 「哪个信息你觉得最有用？哪个最想关掉？」
  2. 「如果这个屏幕只保留三样东西，你们留哪三样？」

### 3.4 T3 双人实拍：一人拍、一人摆（核心任务，对应 G3 + G4）

- **前置**：先问一句「你们平时一般谁拍谁？」按真实分工分配角色——平时常拍的一方持机。
- **任务描述**：「来真的了。请 [持机者] 用 PoseCam 给 [被拍者] 拍一张照，就按屏幕上 AI 说的这个姿势来。被拍的 [被拍者]，请看着屏幕上的轮廓和提示，假装取景框里就是你自己，把你要怎么站、怎么摆**做出来或者说出来**。拍的这位，如果不知道该怎么开口引导 TA，看看 App 里有没有什么东西能帮你。准备好了就开始，觉得拍好了就按快门。」
- **成功标准**：
  - 被拍者能复述或演绎姿势要求（如「侧对窗户、脸转向光、右臂抬高」）；
  - 持机者在 60 秒内、无提示发现并打开「话术锦囊」；
  - 持机者至少念出或化用 1 条话术；完成一次快门、进入 AI 点评页。
- **观察点**：
  - 锦囊入口的发现耗时与路径（直奔橙色按钮？乱点误中？始终没发现？）；打开后对「照着说就好，情绪价值拉满」的反应；会不会点「换几句」；
  - 话术是照读、改写、还是笑场不好意思说；被拍者听到话术时的反应（笑？放松？尴尬？）；
  - 被拍者看静态 SVG 轮廓摆姿势时，是否出现「它怎么知道我摆得对不对」「红线为什么一直亮着」之类疑问（原型无真实姿态检测，属预期差，记录原话即可，不解释）；
  - 手机在两人之间的流转：被拍者会不会凑过来看/抢手机；引导信息（轮廓+提示+话术）在两人之间如何传递，哪里断掉；
  - 整个过程中两人有没有自然对话，还是各自沉默对着屏幕。
- **完成后追问（分开问，先问持机者再避开持机者追问被拍者效果更佳）**：
  1. 问持机者：「这些话术你们真的会照着说出口吗？哪条最说不出口？没有 App 的时候你一般说什么？」
  2. 问被拍者：「光看那个轮廓和一句提示，你清楚自己要怎么摆吗？TA 念那句话的时候你什么感觉？」

### 3.5 T4 换一条建议与焦段（对应 G2）

- **任务描述**：「AI 现在建议的是『侧身靠窗 · 2x 半身特写』，但你想拍一张把人拍全一点、带点环境氛围的。你会怎么办？试一试。」
- **成功标准**：找到并使用 AI 面板的「换一条」，刷出「举杯互动 · 建议焦段 1x · 环境人像」；或主动指向焦段胶囊并表达「我要换焦段」的意图。
- **观察点**：循环箭头图标是否被理解为「换一条建议」；对 1x / 1.5x / 2x 的概念是否清楚；是否试图点击焦段胶囊切换焦段（原型中胶囊仅展示不可点，点击落空即预期差，记录）；换建议后姿势名与提示文案的变化是否被注意到。
- **完成后追问**：
  1. 「你知道 2x、1x 是什么意思吗？平时拍照会调吗？」
  2. 「真拍的时候，你会听 AI 的焦段建议，还是按自己习惯来？」

### 3.6 T5 拍完看点评：保存还是重拍？（顺带目标）

- **任务描述**：「（紧接 T3/T4 的快门；若已离开点评页，主持人代为按一次快门）拍完了，看看这个结果页。告诉我你们看到了什么，接下来想做什么——想做就做。」
- **成功标准**：能说出 8.6 综合分和三个维度（构图 / 姿势 / 情绪）的含义；明确做出「再拍一张」或「保存照片」的选择并给出理由。
- **观察点**：对「姿势 ★★★☆☆ · 右臂线条略僵」的反应（服气？不服？觉得被冒犯？）；三条建议哪条被细读、哪条被跳过；点「保存照片」后出现 Toast「已保存到相册」时，是否追问「照片存哪了 / 这不是刚才那张吧」（原型无真实照片，属预期差，记录原话）；「再拍一张」返回取景器的路径是否顺畅。
- **完成后追问**：
  1. 「这个点评对你们有用吗？哪条会采纳，哪条觉得是废话？」
  2. 「看到姿势只有 3 星，什么感觉？」
  3. 「点评里说『情绪价值拉满』，这种说法你们喜欢吗？」

### 3.7 T6 换模式换场景：我们合照 × 夜景（机动，对应 G1 + G4）

- **任务描述**：「如果接下来想换成你们俩一起合照、在夜景里拍，你们会怎么操作？试试看，到取景器里出现两个人一起的轮廓就算成功。」
- **成功标准**：自行从取景器逐级返回（← 场景 ← 模式），改选「我们合照」+「夜景」，进入取景器并看到双人轮廓。
- **观察点**：返回两级才能改模式，层级是否顺畅；双人轮廓出现时是否注意到与单人的差异；夜景的新建议/新话术会不会被主动翻阅。
- **完成后追问**：「双人轮廓对你们摆合照姿势有帮助吗？还是说你们更习惯自拍杆/定时自拍？」

## 4. 测试形式与预期管理

### 4.1 形式：现场优先、远程备选

- **现场（首选）**：咖啡馆、参与者家中、大学活动室均可；双人同场，便于执行 T3。主持人自备 iPhone 作为测试机，开勿扰模式、亮度调高、电量充足。
- **原型在手机上的打开方式**：电脑在仓库根目录启动本地服务（如 `python -m http.server 8000`），手机连同一 Wi-Fi，Safari 访问 `http://<电脑局域网IP>:8000/prototype-hifi/`，进入后滚动页面隐藏地址栏获得接近全屏的效果；也可「添加到主屏幕」从桌面图标进入。**测试前一天必须完整自测一遍 5 屏**（含锦囊开合、快门跳转、返回路径）。
- **远程（备选）**：腾讯会议/飞书视频，主持人共享手机屏幕（或电脑浏览器开 390×844 设备模拟），参与者口述操作、主持人代点。远程只安排 T1/T2/T5 等单人可完成任务；**T3 双人任务尽量现场做**，远程至多让双人同处一室的参与者执行。
- **记录**：征得同意后用手机自带录屏 + 另一台设备录音；同时主持人纸质/备忘录速记原话。

### 4.2 预期管理：开场标准话术（照读）

> 「开始之前说明三件事：
>
> 第一，今天你们看到的**不是真正的相机 App，是一个可以点击的模型**。它能点、能翻页，但取景框里的画面是假装的效果图，快门不会真的拍照，保存也不会真的存照片。如果哪里点不动、或者行为不像真相机，那是模型本来就这样，**不是你们操作错了**。
>
> 第二，请**假装它是一台真相机**：想象取景框里就是你们俩，该摆姿势摆姿势，该说话说话。
>
> 第三，我们测的是产品设计，不是你们。没有任何对错，卡住、困惑、想吐槽都直接说出来，越真实对我们越有价值。过程中我可能不马上回答问题，是因为想看你们自然的反应，不是故意卖关子。」

### 4.3 主持人守则

- 不主动演示、不教操作；参与者问「这个怎么用」时反问「你觉得呢？」
- 卡住先等 60 秒再按两级提示介入（见 3.1），所有提示记入任务记录表。
- 参与者纠结「为什么拍不了真照片」时，复述一次预期话术并引导：「假装是真的，你接下来会怎么做？」——整场最多复述两次，仍纠结则跳过该环节，避免整场被预期差带偏。
- 全程记录**原话**，不记录二手转述（写「它怎么知道我摆得对不对」，而不是「用户质疑 AR 检测逻辑」）。

### 4.4 单场流程与时间（约 55 分钟）

| 环节 | 时长 | 内容 |
|---|---|---|
| 开场 | 5 min | 预期管理话术 + 知情同意 + 检查录屏录音 |
| 背景了解 | 5 min | 口头过一遍筛选问卷要点（关系、分工、最近一次拍照不愉快经历） |
| 任务测试 | 30 min | T1 → T5（+ 机动 T6） |
| 结束简访 | 10 min | 第 6 节 5 题 + 发酬谢 |
| 缓冲 | 5 min | 整理速记、和参与者闲聊（常有意外的真话） |

## 5. 招募渠道与酬谢

### 5.1 渠道（按优先级，可立即执行）

1. **朋友圈 + 微信群**：发一张信息图（双人一起来 / 45–60 分钟 / 酬谢金额 / 时间地点 / 报名二维码），配一句口语化文案，例：「我在做一个帮人拍好合照的 App，想找几对情侣/闺蜜来试试模型吐吐槽，请喝咖啡 + 红包，感兴趣的私我」。请朋友帮忙转发到二度人脉。
2. **小红书招募帖**，模板要点：
   - 标题钩子：「拍照拍到吵架的情侣看过来｜有偿内测」；
   - 正文写清：我们在做什么（独立开发中的拍照辅助 App，还未上线）、要做什么（线下 45–60 分钟，体验一个可点击的 App 模型并聊天，需情侣/闺蜜**双人同行**）、时间地点、酬谢、报名方式（私信或评论扣 1）；
   - 配图：原型截图做模糊/打码处理，或用氛围感照片，勿泄露完整界面；
   - 话题标签：#情侣拍照 #拍照姿势 #有偿访谈 #产品内测。
3. **大学与社团**：摄影协会、学生会、校园墙/表白墙投稿，适合招 P1 闺蜜组；酬谢门槛低、时间灵活。
4. **同事朋友及其伴侣**：优先「朋友的朋友」而非直系亲属与密友，降低恭维偏差。

### 5.2 酬谢

- **¥50–100 / 场**（按对/组计，不按人头），微信红包当场发；学生场取下限，请假赴约或路程远的场取上限。
- 或等价心意：两杯咖啡 / 一顿饭 / 一次照片打印，提前说明供参与者选择。
- 原则：**到场即付，与表现无关**，避免参与者为了"表现好"而讨好产品。

## 7. 迭代决策规则

| 触发条件 | 动作 |
|---|---|
| 同一点位在 **≥2 场**被卡死（P0） | 必改；改完在下一轮测试中**复测该点位**，确认闭环 |
| 话术锦囊无提示发现率 **< 50%**（发现的场次 ÷ 总场次） | 入口重设计（位置 / 颜色 / 首次进入取景器的气泡引导），下轮必测 |
| 模式或场景含义理解错误 **≥ 1/3 场次** | 改卡片文案与副标题，必要时加示例图；下轮重测 T1 |
| 「信息太多/太乱」被 **≥3 名参与者**主动提及 | 取景器信息分层：AI 面板可收起、提示分级显示、锦囊非拍摄态弱化 |
| AI 点评获「有用」正向评价 **< 50%**（简访 Q2/Q3 综合判断） | 重审点评维度与文案（是否维度不对、建议不 actionable） |
| 使用意愿（1–10）全场次均值 **< 6** | 触发核心价值复盘：是引导执行问题还是需求本身不成立，回到 PRD 讨论定位 |
| 单人孤立意见且非阻断 | 只记录不改；同类建议出现 ≥2 次再排期 |
| **每轮只改 Top 3 问题** | 避免一次改太多导致下轮无法归因 |
