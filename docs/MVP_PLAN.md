# Pose相机 / PoseCam MVP 规划与里程碑

> 版本：v0.1  
> 日期：2026-06-24  
> 基于：`docs/PRD.md`

---

## 1. MVP 目标

在 **6-8 周**内，交付一个可在 iOS TestFlight 上测试的原型，验证核心假设：

> 用户是否愿意为「双向引导（AR 姿势引导 + 构图/焦段建议）+ 情绪话术锦囊」的人像拍摄体验持续使用并付费。

---

## 2. MVP 功能边界

### 2.1 做哪些（In Scope）

| 模块 | 功能 | 说明 |
|---|---|---|
| 拍摄核心 | 相机取景器 | 实时预览，支持前后置切换 |
| | 情侣模式 | 默认模式，优化双人互动 |
| | AR 姿势引导线 | 2D 半透明轮廓，支持缩放/翻转 |
| | 构图辅助框 | 三分法网格 + 人物落点提示 |
| | 焦段建议 | 1x/2x/3x 推荐标签 |
| 话术锦囊 | 预设话术库 | 按场景和拍摄阶段分类 |
| | 实时话术推荐 | 根据当前拍摄状态匹配话术 |
| 模板库 | 20 个基础姿势模板 | 覆盖站/坐/靠/互动等姿势 |
| | 5 个场景模板 | 咖啡馆、海边、展览、公园、室内 |
| 拍摄后 | AI 点评 | 构图/姿势/光线三维度基础评分 |
| | 保存/分享 | 保存相册 + 分享至微信/小红书 |

### 2.2 不做哪些（Out of Scope）

| 功能 | 原因 |
|---|---|
| 动态 LLM 话术生成 | MVP 用规则+模板即可，降低延迟和成本 |
| 表情识别 | 技术复杂度高，留到阶段二 |
| 光线分析 | MVP 阶段用简单曝光提示替代 |
| 社区/UGC | 需要内容运营，MVP 不做 |
| Android 版本 | 先验证 iOS 用户反馈 |
| 机位地图 | 参考可颂的功能，属于阶段二/三 |
| 付费订阅完整链路 | MVP 可模拟订阅入口，先验证点击意愿 |
| AI 实时场景分析 | P1 特性（阶段二，Pro 订阅权益），不在 MVP 范围内 |

## 3. 用户旅程

### 3.1 首次使用流程

```
打开 App → 权限申请（相机/相册/麦克风）→ 新用户引导（3 步）→ 选择模式（默认情侣）
→ 选择场景（咖啡馆）→ 选择姿势模板 → 进入取景器 → 双向引导拍摄 → 查看 AI 点评
→ 保存/分享 → 引导订阅/反馈
```

### 3.2 常规拍摄流程

```
打开 App → 直接进入取景器 → 选择姿势模板 → AR 引导摆姿 → 构图/焦段提示
→ 话术锦囊推荐 → 拍摄 → AI 点评 → 保存/分享
```

## 4. 里程碑计划

### 4.1 里程碑一览

| 阶段 | 周期 | 目标 | 交付物 |
|---|---|---|---|
| **M0：准备** | 第 1 周 | 技术选型确认、项目脚手架搭建、设计规范 | 可运行的空项目、UI 设计稿 |
| **M1：相机基础** | 第 1-2 周 | 相机取景器、前后置切换、基础快门 | 可拍照的 App |
| **M2：AR 引导** | 第 2-3 周 | AR 姿势轮廓叠加、缩放/翻转、匹配度检测 | 姿势引导 Demo |
| **M3：构图建议** | 第 3-4 周 | 构图辅助框、焦段建议、场景识别 | 完整取景器体验 |
| **M4：话术锦囊** | 第 4-5 周 | 话术库、实时推荐、语音播报 | 双向引导完整闭环 |
| **M5：拍摄后** | 第 5-6 周 | AI 点评、保存/分享、用户反馈入口 | 端到端可用版本 |
| **M6：测试优化** | 第 6-7 周 | 内部测试、Bug 修复、性能优化 | TestFlight 候选版 |
| **M7：上线验证** | 第 7-8 周 | TestFlight 发布、种子用户反馈、数据分析 | 验证报告 |

### 4.2 详细里程碑

#### M0：项目准备（第 1 周）

- [ ] 确认技术栈和开发环境
- [ ] 创建 Xcode 项目，配置 SwiftUI + ARKit + Vision
- [ ] 设计 UI 风格指南（色彩、字体、组件）
- [ ] 确定数据模型和接口协议
- [ ] 收集/制作 20 个姿势模板的参考图

#### M1：相机基础（第 1-2 周）

- [ ] 实现 `CameraView`：基于 `AVCaptureSession` 的实时预览
- [ ] 前后置摄像头切换
- [ ] 基础快门拍照，保存到相册
- [ ] 闪光灯、对焦、曝光基础控制
- [ ] 支持 1x/2x/3x 变焦切换

#### M2：AR 姿势引导（第 2-3 周）

- [ ] 集成 Vision 人体姿态检测
- [ ] 实现 `PoseOverlayView`：在取景框上绘制 2D 姿势轮廓
- [ ] 支持姿势模板的缩放、翻转、位置微调
- [ ] 实现姿势匹配度算法（关键点位相似度）
- [ ] 匹配成功提示（轮廓变绿 + 震动）

#### M3：构图建议（第 3-4 周）

- [ ] 实现构图网格线（三分法、中心构图）
- [ ] 实现人物落点提示
- [ ] 基于场景和姿势推荐焦段
- [ ] 简单场景识别（室内/室外/海边/咖啡馆）
- [ ] 手机倾斜/位置偏离提示

#### M4：话术锦囊（第 4-5 周）

- [ ] 构建话术库 JSON（按场景、阶段、问题分类）
- [ ] 实现话术匹配引擎
- [ ] UI：话术气泡/底部提示栏
- [ ] 语音播报（可选，TTS）
- [ ] 根据拍摄状态切换话术（如姿势不对时提示调整）

#### M5：拍摄后体验（第 5-6 周）

- [ ] AI 点评页面 UI
- [ ] 构图/姿势/光线三维度评分逻辑
- [ ] 生成 3-5 条改进建议
- [ ] 保存到相册
- [ ] 分享图片到社交平台
- [ ] 用户反馈入口（简单打分/文字）

#### M6：测试与优化（第 6-7 周）

- [ ] 内部测试（5-10 人）
- [ ] 性能优化（启动速度、AR 延迟、耗电）
- [ ] Bug 修复
- [ ] UI/UX 细节打磨
- [ ] 准备 TestFlight 版本

#### M7：上线验证（第 7-8 周）

- [ ] 提交 TestFlight
- [ ] 邀请 50-100 名种子用户
- [ ] 收集反馈和数据
- [ ] 输出 MVP 验证报告

## 5. 关键假设与验证方式

| 假设 | 验证方式 | 成功标准 |
|---|---|---|
| 用户愿意用 AR 姿势引导摆拍 | 观察首次使用完成率 | ≥ 60% 用户完成首次引导拍摄 |
| 话术锦囊能改善拍照体验 | 用户访谈 + NPS | NPS ≥ 40 |
| 情侣场景是最强需求 | 场景使用分布数据 | 情侣模式使用占比 ≥ 50% |
| 用户愿意为高级功能付费 | 模拟订阅入口点击率 | ≥ 5% 用户点击订阅 |
| AR 姿势引导的精度可接受 | 用户满意度评分 | ≥ 4.0/5.0 |

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对 |
|---|---|---|---|
| AR 姿态估计精度不够 | 中 | 高 | 先降低精度要求，用 2D 轮廓；预留 MediaPipe 备选方案 |
| MVP 开发周期超期 | 中 | 高 | 严格按功能边界执行，必要时削减 P2 功能 |
| 大厂快速跟进 | 中 | 高 | 快速验证 MVP，建立用户粘性和数据壁垒 |
| 用户隐私顾虑 | 中 | 中 | 强调端侧处理，明确隐私政策 |
| iOS 审核不通过 | 低 | 中 | 提前了解相机/AR 类 App 审核规范 |

## 8. 下一步行动

完成本 MVP 规划后，下一步进入 **原型设计（Prototype）** 阶段：

1. 输出 Figma 原型（核心用户旅程）
2. 进行 3-5 人可用性测试
3. 根据反馈调整 PRD 和 MVP 规划
4. 进入开发实现阶段
